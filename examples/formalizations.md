# Formalization examples

A sample of classic philosophical/logical statements, run through
`src/pipeline.py:formalize_fol` (the deterministic FOL → Lean4 stage — no
trained model needed). The FOL is hand-written here to show what the
compiler produces on correct input; the Lean statement is the exact output
of the function, verified by running the code (not hand-typed).

Note: each `theorem ... := by sorry` is only the formalized *statement*, not
a proof — see "Scope" in the README.

---

## Aristotle's syllogism (major premise)

> All men are mortal.

FOL: `∀x (Man(x) → Mortal(x))`

```lean
variable (U : Type)
variable (Man : U → Prop)
variable (Mortal : U → Prop)

theorem socrates_syllogism : ∀ x, (Man x → Mortal x) := by sorry
```

## Cogito ergo sum (Descartes)

> I think, therefore I am.

FOL: `Think(i) → Exists(i)`

```lean
variable (U : Type)
variable (Exists_ : U → Prop)
variable (Think : U → Prop)
variable (i : U)

theorem cogito : (Think i → Exists_ i) := by sorry
```

*(`Exists` in the FOL became `Exists_` in Lean — see "Known limitations".)*

## Law of excluded middle

> For any statement, either it or its negation is true.

FOL: `∀x (P(x) ∨ ¬P(x))`

```lean
variable (U : Type)
variable (P : U → Prop)

theorem excluded_middle : ∀ x, (P x ∨ ¬P x) := by sorry
```

## Law of non-contradiction

> Nothing can both be and not be at the same time, in the same sense.

FOL: `¬∃x (P(x) ∧ ¬P(x))`

```lean
variable (U : Type)
variable (P : U → Prop)

theorem non_contradiction : ¬(∃ x, (P x ∧ ¬P x)) := by sorry
```

## Occam's razor (simplified)

> Among competing hypotheses, the one with fewer assumptions is preferred.

FOL: `∀x∀y (Hypothesis(x) ∧ Hypothesis(y) ∧ SimplerThan(x, y) → Preferable(x, y))`

```lean
variable (U : Type)
variable (Hypothesis : U → Prop)
variable (Preferable : U → U → Prop)
variable (SimplerThan : U → U → Prop)

theorem occams_razor : ∀ x, ∀ y, (((Hypothesis x ∧ Hypothesis y) ∧ SimplerThan x y) → Preferable x y) := by sorry
```

## Socrates' syllogism (full)

> All men are mortal. Socrates is a man. Therefore Socrates is mortal.

FOL: `(∀x (Man(x) → Mortal(x)) ∧ Man(socrates)) → Mortal(socrates)`

```lean
variable (U : Type)
variable (Man : U → Prop)
variable (Mortal : U → Prop)
variable (socrates : U)

theorem full_syllogism : (((∀ x, (Man x → Mortal x)) ∧ Man socrates) → Mortal socrates) := by sorry
```

## Correspondence theory of truth (Aristotle)

> A statement is true if it corresponds to reality.

FOL: `∀p (True(p) ↔ Corresponds(p, reality))`

```lean
variable (U : Type)
variable (Corresponds : U → U → Prop)
variable (True_ : U → Prop)
variable (reality : U)

theorem correspondence_truth : ∀ p, (True_ p ↔ Corresponds p reality) := by sorry
```

*(`True` in the FOL became `True_` — same reason as `Exists` above.)*

## Principle of sufficient reason (Leibniz)

> Everything that exists has an explanation for its existence.

FOL: `∀x (Exists(x) → ∃y (Explains(y, x)))`

```lean
variable (U : Type)
variable (Exists_ : U → Prop)
variable (Explains : U → U → Prop)

theorem sufficient_reason : ∀ x, (Exists_ x → (∃ y, Explains y x)) := by sorry
```

## Disjunctive syllogism (modus tollendo ponens)

> If P or Q, and not P, then Q.

```lean
variable (U : Type)
variable (P : Prop)

theorem disjunctive_syllogism : (((P ∨ Q) ∧ ¬P) → Q) := by sorry
```

## Argument Checker examples

Same rule as above: generated by running `src/pipeline_argument.py:check_argument_fol`
(propositional-only, Phase 1 — see README), not hand-typed. Unlike the
formalizations above, these `theorem`s have no `sorry` — they're real,
Lean-compiled proofs.

### Modus ponens (valid)

> If P then Q. P. Therefore Q.

Premises: `P → Q`, `P` — Conclusion: `Q`

```lean
variable (P : Prop)
variable (Q : Prop)

theorem argument_check (h1 : (P → Q)) (h2 : P) : Q := by
  classical
  by_cases c0 : P <;> by_cases c1 : Q <;> simp_all
```

**Verdict: VALID.** The case-split proof closes for every one of the 4
possible truth assignments of `P`, `Q` — that's what makes it a valid
argument, not just a plausible one.

### Affirming the consequent (invalid)

> If P then Q. Q. Therefore P.

Premises: `P → Q`, `Q` — Conclusion: `P`

```lean
theorem argument_check : ∃ (P : Prop) (Q : Prop), ((False → True)) ∧ (True) ∧ ¬(False) := ⟨False, True, by decide⟩
```

**Verdict: INVALID.** `P = False, Q = True` is a countermodel: both premises
hold (`False → True` is vacuously true; `True` holds) while the conclusion
(`P`) fails — the classic fallacy, caught with an explicit witness rather
than a label.

## Known limitations

- **Name collisions**: a FOL predicate named `Exists` or `True` would shadow
  Lean4's core identifiers (`Exists` is literally what the `∃` notation
  expands to). `src/lean_emit.py` detects a (non-exhaustive) list of
  reserved names and appends `_` — see the Cogito/Leibniz examples above.
  Mathlib adds thousands more names that can collide; the current list only
  covers the common cases expected from a philosophy/logic dataset.
- **`Xor'`**: `⊕` in the FOL (used by FOLIO) has no infix `Prop` notation in
  Lean/Mathlib (there, `⊕` denotes the `Sum` type) — it's emitted as a
  prefix call to Mathlib's `Xor'`.
- **No compile verification**: there's no local Lean toolchain in this
  environment, so the statements above haven't actually been run through
  `lake`/`lean` — only generated and visually verified. On the roadmap (see
  README).
